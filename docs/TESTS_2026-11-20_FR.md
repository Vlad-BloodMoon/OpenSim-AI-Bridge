## Leçons retenues
1. Les erreurs d'authentification initiales provenaient très probablement du mot de passe du compte, corrigé dans ROBUST.
2. La première connexion et les deux commandes IM fonctionnent sans viewer.
3. L'installation doit être simplifiée : **systemd** à la place d'un terminal/screen permanent, statut et opérations via interface Web, arrêt persistant pour utiliser Firestorm.
4. Avant d'activer une IA payante, ajouter des contrôles d'accès par UUID et un système de réponses éditable.
5. Les avertissements CoreJ2K doivent être suivis sans déclarer un bug définitivement résolu.

## Essai correctif CoreJ2K — 23 novembre 2026 à 10:36 (Europe/Paris)

Après déploiement de la DLL compilée par GitHub Actions (run [45148115666](https://github.com/Vlad-BloodMoon/OpenSim-AI-Bridge/actions/runs/45148115666)), l'exploitant a redémarré BloodMoon AI depuis l'interface Web puis extrait les messages du journal `opensim-ai-bridge.service`.

**Observations transmises :**
- 10:36:07 : `Connected in BloodMoon_TEST at <128, 128, 25>`.
- 10:36:12 : plusieurs messages `[XBakes]: Number of alpha wearable textures: 0` et `[Bake]: created head master bake`.
- 10:36:15 : `[BloodMoon AI] Sending AgentSetAppearance (CSB)`.
- **Aucune occurrence** de `Invalid value in 'rate' option: 2.8125` ni de stack trace CoreJ2K dans le résultat filtré fourni.

**Conclusion provisoire :** le correctif `CultureInfo.InvariantCulture` semble résoudre l'erreur d'encodage précédemment reproductible lors du login. L'apparence avait déjà été rapportée normale visuellement avant correction. Ce test confirme l'absence de l'erreur dans l'extrait fourni, pas une garantie d'absence d'autres problèmes. Vérifier lors de connexions futures et surveiller les logs complets si nécessaire.
